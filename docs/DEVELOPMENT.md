# Development workflow

Use small, reviewable tasks.

For each Codex task:
1. read `PROJECT.md`, `TODO.md` and relevant files in `docs/`;
2. explain the intended changes before major architectural changes;
3. modify only what the task requires;
4. add or update tests when behavior is introduced;
5. update documentation if the project structure or decisions change;
6. keep commits small and understandable.

Do not rely on previous Codex conversation context as project memory.
